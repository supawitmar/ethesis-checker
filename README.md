# E-Thesis Staff Checker (standalone web app)

ตรวจเล่ม e-thesis (PDF) เทียบข้อมูลอนุมัติจากบัณฑิตวิทยาลัย — รันเป็นเว็บแอปได้เอง
ไม่ต้องเปิดแชทกับ Claude ทุกครั้ง (นโยบายการตรวจอยู่ในกฎกลาง `ethesis_rules.py`
และตัวประมวลผลอยู่ใน `checker.py`
ระบบ **นับจำนวน** กรรมการให้ว่าครบตามข้อมูลอนุมัติหรือไม่ แต่ **ไม่เทียบชื่อและตัวสะกด**
รายชื่อตาม บฑ. จะพิมพ์ไว้ในรายการสีม่วงให้เจ้าหน้าที่ทานเอง เช่นเดียวกับตำแหน่งวางชื่อ
ในตารางลายเซ็น เพราะแต่ละเล่มจัดหน้าไม่เหมือนกัน)

## ติดตั้งบนเครื่องใหม่

ทุกอย่างที่ต้องใช้อยู่ใน repo นี้แล้ว (ทั้งแอปและด่านตรวจก่อน commit)
โค้ดไม่มี path ตายตัวของเครื่องไหน จึงย้ายเครื่อง/ระบบปฏิบัติการได้เลย

```bash
git clone <repo-url> code
cd code
python -m venv .venv
```

```bash
# Windows PowerShell
.venv\Scripts\Activate.ps1
# macOS / Linux
source .venv/bin/activate
```

```bash
pip install -r requirements.txt -r requirements-dev.txt
cp .env.example .env      # แล้วใส่ APP_PASSWORD (Windows: copy .env.example .env)
```

```bash
python -m unittest discover -s tests
```

ได้ `OK` = พร้อมใช้งาน — จากนั้นดู "รันในเครื่อง" ด้านล่าง

**ข้อควรรู้เรื่องข้อมูลทดสอบ**: ด่าน `tools/regress_books.py` และ
`tools/check_i18n.py --corpus` ใช้ไฟล์วิทยานิพนธ์จริงของนักศึกษา จึง **ไม่อยู่ใน repo**
(ห้าม commit เด็ดขาด) เครื่องที่ไม่มีข้อมูลจะข้ามด่านนั้นพร้อมบอกวิธีเตรียม ไม่พัง
ถ้ามีข้อมูลให้วางไว้ข้าง ๆ repo แบบนี้ หรือตั้ง `ETHESIS_TEST_DIR` ชี้ไปที่อื่น

```text
<โฟลเดอร์แม่>/
├── code/            ← repo นี้
└── test/
    ├── testing/     ← เล่มที่จะตรวจ (1.pdf, 2.pdf, 3.pdf)
    └── ethesis/     ← หน้า eThesis ของเล่มเดียวกัน (1.pdf, 2.pdf, 3.pdf)
```

`python -m unittest` กับ `tools/check_i18n.py --lint` ไม่ต้องใช้ข้อมูลทดสอบเลย
ใช้ได้ทุกเครื่อง

## รันในเครื่อง

```bash
pip install -r requirements.txt
uvicorn main:app --reload
```

เปิด http://localhost:8000

ค่าควบคุมการใช้งาน (environment variables):

- `APP_PASSWORD` — รหัสผ่านเข้าใช้งานระบบ (จำเป็น ต้องตั้งใน Render และห้ามเขียนลง GitHub)
- `SESSION_SECRET` — ค่าสุ่มยาว ๆ สำหรับเซ็นคุกกี้เข้าสู่ระบบ (แนะนำ เก็บเป็น secret บน Render
  เหมือนรหัสผ่าน) ไม่ตั้งก็ใช้ได้ แต่ถ้าคุกกี้หลุด จะเอาไปเดารหัสผ่านแบบออฟไลน์ได้ช้า ๆ
  สร้างด้วย `python -c "import secrets; print(secrets.token_urlsafe(48))"`
  เปลี่ยนค่านี้หรือ `APP_PASSWORD` เมื่อไหร่ ทุกคนต้องเข้าสู่ระบบใหม่
- `MAX_UPLOAD_MB` — ขนาดไฟล์สูงสุด หน่วย MB (ค่าเริ่มต้น 25)
- `MAX_ACTIVE_JOBS` — จำนวนงานตรวจพร้อมกันสูงสุด (ค่าเริ่มต้น 2)
**ระบบนี้ไม่ใช้ AI** ผลตรวจ ข้อความในรายงาน และข้อความสรุปที่คัดลอกส่งนักศึกษา
มาจาก rule engine ล้วน ๆ ผลจึงเหมือนเดิมทุกครั้งที่ตรวจไฟล์เดิม (deterministic)
เคยมีชั้น AI ที่เรียบเรียงข้อความสรุปให้อ่านง่าย ถอดออกแล้วตามคำสั่งเจ้าหน้าที่ ก.ย. 2569

การอัปเดตสรุปเมื่อเจ้าหน้าที่กดปุ่ม: รายการ 🟠/🟡 ที่กด "ไม่ผ่าน" และจุดที่ระบบตรวจเอง
ไม่ได้ซึ่งเจ้าหน้าที่กดเพิ่ม จะถูกรวมเข้าสรุปทันที (เรียก `POST /summary/{job_id}`
สร้างข้อความตรงตัวใหม่) ถ้าอัปเดตไม่สำเร็จจะมีข้อความบอกใต้กล่องคัดลอก

เมื่อ deploy บน Render ให้เพิ่ม `APP_PASSWORD` ในหน้า Environment ของบริการ โดยเลือกเก็บเป็น secret
หากไม่กำหนดค่านี้ ระบบจะแสดงสถานะว่ายังไม่ได้ตั้งรหัสผ่านและไม่อนุญาตให้เข้าหน้าตรวจ

ก่อนสร้างงาน ระบบตรวจว่าไฟล์มีส่วนหัว `%PDF-`, เปิดด้วย `pdfplumber` ได้, มีอย่างน้อย 1 หน้า
และดึงข้อความจากหน้าตัวอย่างได้ หากเป็นไฟล์เสีย มีรหัสผ่าน หรือเป็นภาพสแกนทั้งเล่ม ระบบจะปฏิเสธไฟล์

## ทดสอบ (ด่านก่อน commit)

รันจากโฟลเดอร์ `code/` ทั้งหมด — ต้องผ่านครบทุกข้อก่อน commit ทุกครั้งที่แก้กฎ

```bash
python -B -m unittest discover -s tests
```

```bash
python tools/regress_books.py
```

```bash
python tools/check_i18n.py --lint
```

```bash
python tools/check_i18n.py --corpus
```

| ด่าน | ตรวจอะไร | ต้องมีข้อมูลทดสอบไหม |
|---|---|---|
| `unittest` | ตรรกะทีละกฎ (เร็ว ~1 วิ) | ไม่ต้อง |
| `tools/regress_books.py` | ผลตรวจเล่มจริงต้องไม่เพี้ยนจาก `tools/baseline.json` | **ต้องมี** |
| `tools/check_i18n.py --lint` | โครงสร้างตารางคำแปล `TR` ในหน้ารายงาน | ไม่ต้อง |
| `tools/check_i18n.py --corpus` | ข้อความที่เล่มจริงทำให้เกิด ต้องมีคำแปลอังกฤษครบ | **ต้องมี** |

- **regression เปลี่ยนตัวเลข** ต้องอธิบายให้ได้ว่าทำไม ถ้าอธิบายไม่ได้แปลว่ากฎใหม่
  ทำให้เล่มที่เคยถูกกลายเป็นผิด — ถ้าเปลี่ยนโดยตั้งใจ ให้บันทึกฐานใหม่ด้วย `--save`
- **`--lint` ต้องได้ 0 ทุกบรรทัด** โดยเฉพาะ `entry ที่แยกไม่ออก` — คำแปลที่คร่อมด้วย
  `'...'` แล้วมี apostrophe ข้างในจะทำให้ `<script>` ของหน้ารายงานพังทั้งบล็อกแบบเงียบ ๆ
  (ให้คร่อมด้วย `"..."` แทน)

## Deploy ให้ใช้งานออนไลน์ (ฟรี/ราคาถูก)

ตัวเลือกที่ deploy ง่ายสำหรับแอป FastAPI + Docker แบบนี้:

1. **Render.com** — สมัครฟรี, เชื่อม GitHub repo, เลือก "Web Service", Render
   จะ build จาก Dockerfile ให้อัตโนมัติ (มี free tier ที่ sleep เมื่อไม่ใช้งาน)
2. **Railway.app** — คล้าย Render, deploy จาก GitHub หรือ CLI (`railway up`)
3. **Fly.io** — `fly launch` จะอ่าน Dockerfile ให้เอง เหมาะถ้าต้องการ custom domain

ขั้นตอนทั่วไป (ตัวอย่าง Render):
1. Push โฟลเดอร์นี้ขึ้น GitHub repo
2. ที่ Render → New → Web Service → เชื่อม repo
3. Render ตรวจเจอ Dockerfile อัตโนมัติ → กด Deploy
4. ได้ URL สาธารณะ เช่น `https://ethesis-checker.onrender.com`

## โครงสร้างไฟล์

- `main.py` — FastAPI app: หน้าแบบฟอร์ม (`/`) + endpoint ตรวจ (`/check`)
- `ethesis_rules.py` — กฎกลาง: วิธีเทียบข้อความ เกณฑ์ typo และขอบเขตการตรวจส่วนเนื้อหา
- `RULES_AND_SOURCES.md` — ตารางกฎ ลำดับอำนาจ และเลขข้อ/หน้าของประกาศฯ กับคู่มือ
- `checker.py` — ประมวลผล PDF ตามกฎกลางและสร้างรายการผลตรวจ
- `ethesis_import.py` — อ่านหน้า eThesis (บฑ.1/บฑ.2) มาเติมฟอร์มให้อัตโนมัติ
- `templates/index.html` — ฟอร์มกรอกข้อมูล + อัปโหลด PDF
- `templates/report.html` — หน้าแสดงผลตรวจ (โซนสี 🔴🟠🟡) + ตารางคำแปลอังกฤษ `TR`
- `tests/` — unittest ทั้งหมด (ไม่ต้องใช้ไฟล์ PDF)
- `tools/` — ด่านตรวจก่อน commit: `regress_books.py`, `check_i18n.py`, `baseline.json`
- `.claude/` — คู่มือทำงานสำหรับ Claude Code (ขั้นตอนแก้กฎ + กับดักเฉพาะโปรเจกต์)
  กับ `launch.json` ของ dev server · **เปิด Claude Code ที่โฟลเดอร์ `code/` นี้**
  จึงจะเจอเอง · ไม่เกี่ยวกับการรันหรือ deploy ระบบเลย (`.dockerignore` ตัดออกอยู่แล้ว)

## ข้อจำกัดเทียบกับชุด Claude Skill เดิม

- ส่วนเนื้อหาไม่ตรวจการสะกด ไวยากรณ์ หรือความถูกต้องเชิงวิชาการทุกบรรทัด ระบบใช้เฉพาะ
  หัวหน้าบทเพื่อหาตำแหน่ง แล้วตรวจเลขหน้าเรียงต่อกัน การมีบทในสารบัญ และเลขหน้าตรงกับสารบัญ
- ข้อความอ้างอิง เช่น ชื่อเรื่อง ชื่อ และชื่อปริญญา แยกผลเป็นตรงทุกตัวอักษร,
  ตัวพิมพ์เล็ก-ใหญ่ไม่ตรง, พิมพ์ผิดเล็กน้อย (typo), หรือข้อความไม่ตรง โดยแสดงทั้งค่าที่พบและค่าที่ควรเป็น
- **ชื่อปริญญากรอกแยกตามตำแหน่งที่ใช้ตรวจ 3 คู่** (อังกฤษ/ไทย): หน้าปก = ต้นฉบับจาก eThesis,
  หน้าลงนาม = Sentence case (ไทยคงเดิม), บทคัดย่อ = ชื่อย่อ — ระบบเติมให้จาก eThesis และแก้ไขได้
  ต่างเฉพาะวรรคตอน/ช่องว่าง = สีส้ม, สะกดผิด = สีแดง
- **รหัสนักศึกษาต้องกรอกทั้งเลข 7 หลักและรหัสหลักสูตร** เช่น `6838141 SHSS/M`
  ตรวจในบทคัดย่อทุกภาษาที่เล่มมี (นานาชาติตรวจเฉพาะบทคัดย่ออังกฤษ)
- ตั้งแต่หน้าปกถึงหน้าบทคัดย่อใช้การตรวจอย่างเข้ม: ช่องอ้างอิงในแบบฟอร์มต้องกรอกครบ
  และทุกตำแหน่งที่กำหนดต้องตรง หากผิด ขาด หรือมี typo จะเป็นผลสีแดง
- ตรวจข้อความบังคับบนหน้าปกตามประเภทและภาษาของเล่ม, ชื่อผู้เขียนท้ายกิตติกรรมประกาศ,
  ความครบถ้วน/ลำดับส่วนนำ และหัวข้อสำคัญพร้อมเลขหน้าในสารบัญเป็นสีแดง

- รายงานแสดง "ผลเทียบข้อมูลอนุมัติรายตำแหน่ง" เสมอ (ชื่อเรื่อง/ชื่อนักศึกษา/รหัส/ปริญญา/
  วันสอบ/ปี พร้อมระบุหน้าที่เทียบและผล ตรง/ไม่ตรง/รอยืนยัน) แม้ทุกจุดจะตรงก็แสดง
- ไม่ตรวจขนาดกระดาษ/margin/line-spacing/font (เหมือนเดิม — ชุดเจ้าหน้าที่ตรวจ PDF ไม่ได้ตรวจสิ่งเหล่านี้)
- ไม่ตรวจรายชื่อ/บทบาทกรรมการ ตำแหน่งในตารางลายเซ็น และข้อความมุมล่างขวาโดยอัตโนมัติ
  รายงานจะแสดง checklist ให้เจ้าหน้าที่ตรวจเอง
- ไม่ตรวจ plagiarism, PDF/A, embedded fonts และความคมชัดของภาพ
- ไม่ตรวจการมี/ไม่มีลายเซ็น ความแท้จริงของลายเซ็น ขั้นตอน/กำหนดเวลาส่งเล่ม หรือสิทธิ์เผยแพร่
- การจำแนก typo ใช้ `difflib` (ในตัว Python) และเกณฑ์จาก `MATCH_RULES` ใน `ethesis_rules.py`
- ผลคำว่า “ผ่าน” หมายถึงผ่านเฉพาะรายการที่ระบบตรวจได้ รายการนอกขอบเขตจะแสดงท้ายรายงานเสมอ
